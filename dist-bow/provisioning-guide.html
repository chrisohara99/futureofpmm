SAP Provisioning Guide

Step-by-step instructions for deploying Future of PMM on SAP infrastructure

Hi Sean — This guide walks you through exactly how to provision the Future of PMM site on SAP corporate infrastructure. The site is static HTML with zero dependencies, so deployment is straightforward.

1

Download the Site Package

First, download all the site files. You have two options:

Option A: Download ZIP from Netlify

  1. Go to the current live site: bow-demo-pmm.netlify.app
  2. Contact Chris O'Hara for the Netlify account access, or request a ZIP export

Option B: Clone from GitHub (Recommended)

Once the repo is created on SAP GitHub Enterprise:

# Clone the repository git clone https://github.tools.sap/CMO/Future-of-PMM.git # Navigate to the site folder cd Future-of-PMM/dist-bow # This folder contains everything needed for deployment ls -la
📁 What you'll get: ~120 HTML files, organized into /bow/ (Book of Work areas) and /newsletter/ (archive). Total size: ~5MB.
2

Choose Your Hosting Platform

SAP has several options for internal static sites. Here are the most common:

Platform Best For Complexity
SAP BTP Static File Hosting Official SAP cloud hosting Medium
GitHub Pages (github.tools.sap) Quick deployment, version control Easy
Internal Web Server Existing infrastructure Varies
SharePoint Integration with MS365 Easy
💡 Recommendation: GitHub Pages on github.tools.sap is the fastest path. It auto-deploys when you push changes and handles SSL automatically.
3

Deploy via GitHub Pages (Easiest)

If using SAP's internal GitHub:

3a. Create the Repository

  1. Go to github.tools.sap
  2. Create new repo under the CMO organization: CMO/Future-of-PMM
  3. Set visibility to "Internal" (accessible to all SAP employees)

3b. Push the Files

# Initialize and push cd dist-bow git init git add . git commit -m "Initial deployment of Future of PMM" git remote add origin https://github.tools.sap/CMO/Future-of-PMM.git git push -u origin main

3c. Enable GitHub Pages

  1. Go to repo Settings → Pages
  2. Source: Deploy from branch
  3. Branch: main, folder: / (root)
  4. Click Save
✅ Done! Your site will be live at: https://pages.github.tools.sap/CMO/Future-of-PMM/
4

Deploy via SAP BTP (Alternative)

If you need to use SAP Business Technology Platform:

4a. Prerequisites

  • SAP BTP account with Cloud Foundry enabled
  • CF CLI installed
  • Entitlement for Static File Hosting or HTML5 Application Repository

4b. Create manifest.yml

Add this file to the dist-bow folder:

# manifest.yml applications: - name: future-of-pmm memory: 64M disk_quota: 256M buildpack: staticfile_buildpack path: . routes: - route: future-of-pmm.cfapps.sap.hana.ondemand.com

4c. Deploy

# Login to Cloud Foundry cf login -a api.cf.sap.hana.ondemand.com # Deploy the app cf push
5

Configure Custom Domain (Optional)

If you want a custom URL like futureofpmm.sap.com:

  1. Submit a request to SAP IT for DNS configuration
  2. Provide the target URL from your deployment (GitHub Pages or BTP)
  3. Request SSL certificate provisioning
  4. IT will configure the CNAME record to point to your hosting
⏱️ Timeline: Custom domain setup typically takes 1-2 weeks through IT ticketing system.
6

Verify Deployment

After deployment, verify everything works:

  • Homepage loads at root URL
  • Navigation links work (Home, Book of Work, Newsletter)
  • All 19 Book of Work area pages load
  • Articles within each area are accessible
  • Newsletter archive displays correctly
  • Mobile responsive design works (test on phone)
  • HTTPS is working (no certificate warnings)

Test URLs to Check

/ # Homepage /bow/ # Book of Work hub /bow/messaging-positioning/ # Sample BoW area /bow/messaging-positioning/human-premium.html # Sample article /newsletter/ # Newsletter archive /handoff.html # IT documentation
7

Set Up Redirects (If Needed)

If users have bookmarks to the old site structure, you may want to set up redirects:

Old URL Redirect To
/curriculum/unit-01/ /bow/messaging-positioning/guide-01.html
/curriculum/* /bow/
/newsletters/* /newsletter/

For GitHub Pages, create a 404.html with JavaScript redirects. For BTP/web servers, configure server-side redirects.

✓

Summary

That's it! The site is pure static HTML, so once the files are on a web server, it just works. No databases, no server configuration, no build process.
